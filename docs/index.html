A terminal multiplexer for coding agents.

A detachable daemon keeps the PTYs alive. A Bubble Tea client attaches and detaches at will. And the agents drive the whole thing over a JSON-RPC socket — spawning each other, watching each other's status, blocking until each other's work is done.

The model

Workspaces hold tabs, tabs hold panes.

A session holds workspaces, a workspace holds tabs, a tab holds a layout of panes. One workspace per repo or task, tabs to separate views inside it, panes split right and down. Ids say where something lives: w1, w1:t2, w1:p3.

▸Workspaces follow your directory

cd somewhere else and the name and git branch change with it. Name one yourself and the name sticks — but the directory and branch keep tracking, because a name is a choice and a stale branch is just wrong.

▸Agents named by what they're doing

Read from the terminal title the agent sets — "Refactor the parser", not four rows all reading claude. A manual rook pane rename always wins.

▸Only agents in the agents panel

Plain shells are deliberately left out: the panel answers "who needs me", and a shell sitting at a prompt is not an answer.

▸The layout survives a restart

Workspaces, tabs, the split tree and its ratios are saved whenever they change and read back at startup. Panes return as a shell in the directory they were in — relaunching eight agents isn't a decision a multiplexer should make for you.

▸Scroll, select, copy over OSC 52

prefix [ scrolls back through the pane's transcript. Copying goes through OSC 52, so it reaches your real clipboard even at the far end of an SSH connection.

▸Mouse, menus and a fuzzy jump

Click to focus, drag a divider to resize, right-click any pane, tab or workspace for a context menu. prefix f fuzzy-finds every agent, workspace and tab.

Agent-aware

Which agent wants you, at a glance.

Every pane carries a status glyph — in the sidebar and in its own header. A workspace row carries its aggregate status, so a workspace with a blocked agent inside looks different from a merely idle one even with colour turned off.

Detection you can correct

Status comes from prioritised rules in per-agent manifests. The built-in set is embedded, so it works with nothing on disk — and a file in ~/.rook/agents with the same id replaces a built-in rather than fighting it.

rook agents ls            # known agents, rule counts
rook agents show claude   # one manifest, rules and all
rook agents init          # copy the built-ins to edit

Integrations beat heuristics

Screen detection is a guess; an integration replaces it with facts. Claude Code's hook events map exactly onto rookery's three states, and OpenCode's plugin events cover every transition. Codex reports its session id. A fresh report wins over the screen — and if the reports stop, rookery falls back to reading the screen rather than leaving a pane stuck busy.

rook setup                        # interactive wizard
rook integration status            # every config found
rook integration install claude
rook report --status blocked --agent mine

Fan-out

One prompt, several agents, one checkout each.

Each agent gets its own tab, its own worktree, and its own branch rook/<name>-<n>. Three agents on one task therefore cannot fight over the index, and comparing their answers is a diff rather than three transcripts. 

rook fan "make the flaky auth test pass" --agents 3
rook watch --status done,blocked   # tell me when they land
rook fan ls                          # who did what
rook fan review fan1                 # compare candidates
rook fan promote fan1 fan1-2 --apply # ff a clean winner
rook fan clean fan1 --force          # bin the rest
rook fan ls
fan1  w1:p2  done     rook/fan1-1  2 files changed, 31 insertions(+)
fan1  w1:p3  blocked  rook/fan1-2  1 file changed, 4 insertions(+)
fan1  w1:p4  done     rook/fan1-3  1 new file(s)

Untracked files are counted separately on purpose: git diff ignores them, so an agent whose whole contribution was a new file used to look like it had done nothing. fan clean is all-or-nothing — if any worktree has uncommitted work it removes nothing and says which. fan promote --apply only fast-forwards a clean source branch to a clean candidate, and keeps every worktree so nothing is destroyed while you inspect the result.

Automation API

Built to be driven by the agents inside it.

Every pane gets ROOK_SESSION, ROOK_PANE and ROOK_ENV=1, so an agent inside a pane can drive rookery with no configuration. Every rook pane and rook wait subcommand prints the raw API result as indented JSON, so a tool call parses one output dialect.

Spawn, send, read

rook pane current                  # which pane am I?
rook pane new --label reviewer --no-focus -- claude
rook pane send p2 review the current diff
rook pane read p2 --scrollback --lines 60 --raw
rook api pane.list                 # any method, raw

Input is measured, not assumed: the Enter is a separate keypress 150 ms after the text, because text and its carriage return in one write look like a paste and land in the composer. Messages queue until the agent's UI is actually up, so a fan-out of five doesn't quietly become a fan-out of two.

Block instead of poll

rook pane send p2 run the test suite
rook wait agent-status p2 --status done,blocked \
    --timeout 300000 && rook pane read p2 --raw

rook wait blocks in the daemon until the pane reaches a wanted state — exit 0 on a match, 1 on timeout, so it chains. It works for plain commands too: the daemon asks the kernel which process group owns the PTY, so a shell running sleep 30 is working even though it prints nothing.

rook watch --status blocked | while read -r ev; do
    say "$(jq -r .label <<<"$ev") needs you"
  done

rook watch streams NDJSON — agent_status, pane_new, pane_closed, pane_exit — one flat JSON object per line, every field one jq hop away. Events are dropped rather than queued without bound if a consumer falls behind, and the drop is counted rather than hidden.

rook skill --install writes the agent-facing skill into the config your agent actually loads: how to spawn siblings without stealing focus, how to wait instead of poll, how to fan a task out, and the etiquette of not killing panes it did not create. It tells the agent to do nothing unless ROOK_ENV=1.

Remote attach

SSH carries the terminal. Nothing else moves.

If rookery is installed on a machine you can reach over SSH, its daemon and PTYs stay entirely on that machine; your local terminal just runs the remote attach client.

SSH owns authentication, host aliases and connection recovery. This is deliberately not a network-exposed rook socket: the remote daemon keeps using its local Unix sockets and SSH carries only the interactive terminal.

rook attach review --remote devbox
rook --remote devbox review   # equivalently

Install

One Go binary.

go build -o rook ./cmd/rook
./rook   # attach the default session, starting the daemon

Or via the justfile:

just install   # rook on your PATH, daemon restarted
just setup     # that, plus the hooks and the agent skill

Which is go install ./cmd/rook — no copy step, no sudo. The justfile is there for the part that's easy to forget: a new binary changes nothing until the running daemon goes away, so install kills it. The client says so itself when the two versions differ.

Configuration is optional

~/.rook/config.json and hotkeys.json are written with their defaults on first run, so the files document themselves. Anything you leave out keeps its default.

{ "ui": {
    "icons": "nerd",
    "spinner": "dots",
    "pane_borders": "auto",
    "blink": true,
    "mouse_capture": true,
    "sound": { "mode": "system", "desktop": true },
    "colors": {
      "accent": "#7aa2f7", "blocked": "3",
      "done": "2", "working": "6",
      "sidebar_bg": "235", "border": "238"
    }
} }

Colours are ANSI indices, 256-colour indices or hex. Status colours default to low ANSI slots so they follow the theme your terminal already uses.

Deliberate limits

Not in this version

Character-accurate scrollback and drag-to-select, plugins, and per-client viewports (the daemon renders one frame at the last attacher's size). Scrollback is the plain-text transcript the daemon already keeps — 2000 lines, no colour — and selection is by whole lines; cell-accurate styled history is a different program. See future-plan.md.

No built-in git UI

prefix G opens whichever of lazygit, gitui or tig you have, in the active workspace's directory, falling back to a shell with git status printed. lazygit is better than anything a multiplexer would grow on the side, and a pane is exactly the right place to put it.

Mouse capture costs native selection

While capture is on, your terminal's own text selection needs shift+drag — the same trade tmux makes. prefix m toggles it, or set "mouse_capture": false.
